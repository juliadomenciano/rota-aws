Route 53: DNS gerenciado

DNS é a agenda da internet: traduz app.empresa.com em IP. O Route 53 registra domínios, responde consultas (com SLA de 100% de disponibilidade) e faz health checks para tirar endpoints doentes da resposta.

RegistroAponta paraObservação
A / AAAAIPv4 / IPv6—
CNAMEOutro nomeNão pode ficar no domínio raiz (apex)
AliasRecursos AWS (ALB, NLB, CloudFront, S3 website, API Gateway, outro registro da zona)Funciona no apex, consultas grátis, acompanha mudança de IP
MX, TXT, NS, SOAE-mail, verificação, servidores de nome—
  • Public hosted zone: responde na internet. Private hosted zone: só dentro das VPCs associadas.
  • Route 53 Resolver endpoints: inbound (on-premises resolve nomes da AWS) e outbound (VPC resolve nomes do on-premises).
Pegadinha: apontar empresa.com (sem www) para um ALB ou CloudFront = registro Alias. CNAME no apex não existe.

Amazon CloudFront (CDN)

  • Origens: S3, ALB, EC2, API Gateway, qualquer HTTP. Origin groups fazem failover entre origens.
  • Cache behaviors: regras por caminho (/static/* com TTL longo; /api/* sem cache e para outra origem).
  • TTL e cache policies definem por quanto tempo e com quais chaves (headers, cookies, query) o objeto fica em cache.
  • Invalidation remove do cache antes do TTL (ou versione o nome do arquivo: app.3f9a.js).
  • OAC (Origin Access Control, sucessor do OAI): bucket privado que só o CloudFront lê.
  • Signed URLs (um arquivo) e signed cookies (vários arquivos) para conteúdo pago.
  • Geo restriction por país, integração com WAF e Shield, HTTPS com ACM (certificado em us-east-1).
  • CloudFront Functions (leve, cabeçalhos e redirects) e Lambda@Edge (mais poder, acesso à rede).
Pegadinha: pre-signed URL do S3 ≠ signed URL do CloudFront. Para entregar conteúdo pago por CDN com bucket privado: CloudFront + OAC + signed URLs/cookies.

AWS Global Accelerator

Dá 2 IPs anycast estáticos globais. O usuário entra na rede da AWS pela Edge Location mais próxima e segue pelo backbone até o endpoint (ALB, NLB, EC2, Elastic IP) da Região saudável mais próxima. Failover em segundos, sem depender de cache de DNS.

Amazon ElastiCache

Cache em memória gerenciado: respostas em sub-milissegundos e menos carga no banco. Também é o lugar clássico para guardar sessões e deixar a aplicação stateless. Exige mudança no código da aplicação.

Lazy loading (cache-aside)Busca no cache; se não tem, lê do banco e grava no cache. Só guarda o que é pedido; pode ficar desatualizado.

TTLExpira chaves para limitar dados velhos. Combine com as duas estratégias.
