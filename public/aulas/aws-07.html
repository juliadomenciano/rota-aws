S3 em poucas linhas

  • Armazenamento de objetos: arquivos via API HTTP, sem sistema de arquivos. fotos/2026/a.jpg é só a key do objeto; "pastas" são prefixos.
  • Bucket: nome globalmente único, mas o bucket vive em uma Região.
  • Objeto: até 50 TB (o limite era 5 TB até dez/2025; questões antigas ainda citam 5 TB). Upload simples (PUT) até 5 GB; acima disso, multipart.
  • Durabilidade de 11 noves (99,999999999%) em quase todas as classes; disponibilidade varia por classe.
  • Consistência forte de leitura após gravação para PUT e DELETE.

Limites de tamanho e de requisições mudam. Confirme no guia do usuário do S3.

Lifecycle rules

Movem objetos para classes mais baratas por idade (transition) e apagam depois de um tempo (expiration), inclusive versões antigas e uploads multipart incompletos. Ex.: Standard → 30 dias Standard-IA → 90 dias Glacier Flexible → 7 anos apagar.

Pegadinha: "padrão de acesso desconhecido" = Intelligent-Tiering. "Dados podem ser recriados" = One Zone-IA. "Precisa de acesso em milissegundos mas é raríssimo" = Glacier Instant Retrieval. "Pode esperar até 48 horas e o mais barato" = Deep Archive. E use S3 Storage Class Analysis para descobrir quando transicionar.

Preços, tempos de recuperação e mínimos de cobrança podem mudar. Confirme na página de classes do S3.

Proteção de dados

  • Versionamento: guarda todas as versões; um DELETE cria um delete marker (dá para recuperar). Depois de ligado, só pode ser suspenso.
  • MFA Delete: exige MFA (do root) para apagar versões definitivamente ou mudar o versionamento.
  • Object Lock (WORM): impede apagar ou sobrescrever por um período. Modo Governance (quem tem permissão especial pode remover) e Compliance (ninguém, nem o root). Legal hold sem prazo.
  • Replicação: exige versionamento nos dois lados. CRR (outra Região: DR, compliance, latência) e SRR (mesma Região: agregar logs, cópia entre contas). Só replica objetos novos; para os antigos, use S3 Batch Replication. RTC garante 99,99% em 15 minutos.
