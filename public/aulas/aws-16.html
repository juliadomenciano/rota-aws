Migrando servidores e bancos

AWS Application Migration Service (MGN)Rehost: replica continuamente os discos dos servidores (físicos, VMware, Hyper-V, outra nuvem) para a AWS e faz o cutover com pouca parada.
AWS DMSMigra bancos com o origem funcionando: carga completa + CDC (replicação contínua das mudanças). Também replica continuamente entre bancos.
Schema Conversion (DMS SC / SCT)Converte schema e código entre engines diferentes (Oracle → Aurora PostgreSQL). Migração homogênea (MySQL → MySQL) não precisa de conversão.
VM Import/ExportImportar imagens de VM como AMIs.
Pegadinha: "migrar o banco com o mínimo de indisponibilidade" = DMS com CDC. "Engines diferentes" = DMS + Schema Conversion.

Snow Family hoje

O Snowcone foi descontinuado (nov/2024), o Snowmobile foi aposentado e o Snowball Edge não aceita novos clientes desde 07/11/2025. Para contas novas, a AWS recomenda DataSync (online), AWS Data Transfer Terminal (levar os discos a um local físico da AWS) ou parceiros; para computação na borda, Outposts. Na prova, porém, "petabytes com rede lenta, transferência offline" ainda costuma ter Snowball Edge como resposta.

Conta rápida: 100 TB em um link de 100 Mbps leva mais de 90 dias. Se a rede não dá conta no prazo, a resposta é transferência física.

RPO e RTO

RPOQuanto de dados posso perder (tempo entre o último backup/replicação e o desastre)."Podemos perder no máximo 15 minutos de transações."
RTOQuanto tempo posso ficar fora do ar até voltar."Precisamos voltar em até 1 hora."

Quanto menores RPO e RTO, mais caro. A questão sempre dá os números; escolha a estratégia mais barata que os atende.
