O problema e as duas ferramentas

Uma instância sozinha é ponto único de falha e não escala. A dupla clássica resolve as duas coisas:

Elastic Load BalancingDistribui o tráfego entre vários alvos e tira do rodízio quem falha no health check.
Auto ScalingLiga e desliga instâncias conforme a demanda e substitui as doentes.

Peças: Listener (porta + protocolo) → Rules (no ALB: caminho, host, header, query) → Target group (EC2, IPs, Lambda, ou outro ALB no caso do NLB) com health check.

Auto Scaling group (ASG)

  • Launch template: a receita (AMI, tipo, SG, user data, role). Prefira launch template a launch configuration (legado).
  • Mínimo / desejado / máximo: piso, alvo atual e teto.
  • Health checks: EC2 (a máquina responde) e ELB (a aplicação responde). Ative o do ELB para substituir instâncias com app travado.
  • Distribui as instâncias entre as AZs configuradas e rebalanceia.

  • Warm pools: instâncias pré-inicializadas e paradas, prontas para entrar rápido (apps com boot lento).
  • Lifecycle hooks: pausar a instância ao entrar ou sair para rodar algo (instalar agente, copiar logs).
  • Instance refresh: trocar todas as instâncias para uma nova AMI aos poucos.
  • Mixed instances policy: combinar On-Demand e Spot e vários tipos no mesmo ASG.

A arquitetura de alta disponibilidade

ALB + ASG em pelo menos duas AZs é a resposta para "tolerante a falhas, escalável e auto-recuperável". O ASG registra e desregistra as instâncias no target group sozinho.

Sessão na instânciaUsuário perde o login quando a instância some ou quando o ALB manda para outra.
App statelessSessão no ElastiCache ou no DynamoDB; qualquer instância atende qualquer usuário.
Pegadinha: Auto Scaling é horizontal (mais instâncias). Aumentar o tipo da instância (vertical) exige parar e tem teto. A prova prefere escalar na horizontal.

HTTPS no load balancer

  • ACM (AWS Certificate Manager): certificados públicos grátis com renovação automática para ALB, NLB, CloudFront e API Gateway.
  • TLS termination (offload): o load balancer descriptografa e alivia as instâncias. Se precisar de criptografia ponta a ponta, use HTTPS também até o alvo.
  • SNI: vários certificados (vários domínios) no mesmo listener HTTPS do ALB ou do NLB.
  • Security policy: define versões de TLS e cifras aceitas (ex.: só TLS 1.2+).
  • Redirect HTTP → HTTPS: regra do ALB na porta 80.
