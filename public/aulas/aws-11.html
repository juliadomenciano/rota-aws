AWS Lambda

Você envia o código; a AWS roda quando chega um evento, escala sozinha e cobra por requisição e por duração (GB-segundo). É stateless: nada de guardar sessão na memória da função.

Limite ou recursoValor / uso
Timeout máximo15 minutos. Passou disso: Fargate, AWS Batch, EC2 ou dividir com Step Functions
Memória128 MB a 10.240 MB; a CPU cresce junto com a memória
/tmpAté 10 GB de armazenamento efêmero
PacoteZip ou imagem de container (até 10 GB)
ConcorrênciaCota regional compartilhada. Reserved concurrency garante e limita uma função; provisioned concurrency deixa instâncias aquecidas (sem cold start)
VPCPode acessar recursos privados (RDS); para internet precisa de NAT
LayersCompartilhar bibliotecas entre funções
  • Invocação síncrona (API Gateway, ALB): quem chama espera a resposta. Assíncrona (S3, SNS, EventBridge): a Lambda tenta de novo e pode mandar falhas para uma DLQ ou destination. Event source mapping (SQS, Kinesis, DynamoDB Streams): a Lambda busca os registros em lote.
  • RDS Proxy: agrupa conexões quando milhares de Lambdas acessam um banco relacional.

Limites de memória, payload e concorrência mudam. Confirme nas cotas do Lambda.

API Gateway e Cognito

TipoQuando usar
REST APIRecursos completos: API keys e usage plans, cache de respostas, validação de requisição, WAF, endpoint privado
HTTP APIMais simples, mais barata e com menor latência; JWT/Cognito, Lambda e HTTP como backend
WebSocket APIComunicação bidirecional em tempo real (chat, painéis ao vivo)
  • Throttling protege o backend; usage plans + API keys limitam cada cliente; cache evita chamar o backend para respostas iguais.
  • Endpoints: edge-optimized (via CloudFront), regional, private (só pela VPC via interface endpoint).
  • Autorização: IAM (SigV4), Cognito user pools (JWT) ou Lambda authorizer (lógica própria, tokens de terceiros).

Amazon SQS: filas

A fila fica entre quem produz e quem consome. Se o consumidor cai ou fica lento, as mensagens esperam. É a ferramenta número 1 de desacoplamento e de absorção de picos.

StandardFIFO
OrdemMelhor esforçoExata (por message group)
EntregaPelo menos uma vez (pode duplicar)Exatamente uma vez (deduplicação)
ThroughputPraticamente ilimitadoAlto, mas limitado (maior com high throughput mode e batch)
  • Visibility timeout: tempo em que a mensagem some para os outros consumidores enquanto alguém processa. Se o processamento demora mais, a mensagem reaparece e é processada duas vezes: aumente o timeout.
  • Dead-letter queue (DLQ): após N tentativas (maxReceiveCount), a mensagem vai para outra fila para análise.
  • Long polling: o consumidor espera até 20 s por mensagens; menos chamadas vazias e menos custo.
  • Retenção de 1 minuto a 14 dias (padrão 4 dias). Delay queue atrasa a entrega.
  • Escala de consumidores: Auto Scaling de EC2/ECS pela métrica ApproximateNumberOfMessagesVisible (backlog por instância).

O tamanho máximo da mensagem passou de 256 KiB para 1 MiB em ago/2025. Questões antigas ainda falam em 256 KB; para arquivos grandes, a resposta é guardar no S3 e mandar só a referência.

SNS e EventBridge

Amazon SNSPub/sub: uma mensagem publicada no tópico é empurrada para todos os inscritos (SQS, Lambda, HTTP, e-mail, SMS). Filtros por atributos. Há tópicos FIFO.
Fan-outSNS → várias filas SQS: cada sistema processa no seu ritmo e nada se perde se um estiver fora.
Amazon EventBridgeBarramento de eventos com regras e filtros por conteúdo, eventos de serviços AWS e de SaaS parceiros, entrega para muitos destinos, replay e arquivo. O Scheduler agenda tarefas (cron).
Preciso de...Use
Bufferizar trabalho para um consumidor processar no seu ritmoSQS
Ordem estrita e sem duplicidadeSQS FIFO
Avisar vários sistemas ao mesmo tempoSNS (+ SQS para fan-out durável)
Reagir a eventos de serviços AWS ou SaaS com filtros ricosEventBridge
Rodar algo todo dia às 2hEventBridge Scheduler
Fluxo com várias etapas, decisões, esperas e retryStep Functions
Stream de dados em tempo real com replay e vários consumidoresKinesis Data Streams (aula 12)
Migrar app que usa JMS/AMQP/MQTT sem reescreverAmazon MQ

AWS Step Functions

Orquestra um workflow como máquina de estados visual: tarefas em sequência, escolhas (if), paralelismo, mapas sobre listas, esperas, retry e captura de erro, chamando Lambda, ECS, SQS, DynamoDB e mais de 200 serviços.

  • Standard: até 1 ano, exatamente uma vez, auditável. Express: alto volume e curta duração (até 5 min), mais barato.
  • Ótimo para quebrar um processo que passaria dos 15 minutos da Lambda e para aprovação humana (callback com task token).
