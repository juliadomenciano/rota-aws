Infraestrutura como código

Descrever a infraestrutura em arquivos versionados no Git: repetível entre ambientes e Regiões, revisável em PR e fácil de recriar depois de um desastre.

FerramentaO que éQuando usar

  • Change sets: ver o que vai mudar antes de aplicar.
  • Drift detection: descobrir mudanças feitas na mão fora do template.
  • StackSets: implantar a mesma stack em várias contas e Regiões (ótimo com Organizations).
  • DeletionPolicy: Retain/Snapshot: proteger bancos e buckets ao apagar a stack.
  • Parameters, Mappings, Outputs e referências a outros stacks.

AWS Elastic Beanstalk

PaaS: você envia o código (Node, Java, Python, .NET, PHP, Go, Docker) e o Beanstalk cria e gerencia EC2, Auto Scaling, load balancer, monitoramento e deploy. Você mantém acesso aos recursos por baixo.

Política de deployComportamento
All at onceMais rápido, com indisponibilidade
RollingEm lotes, com capacidade reduzida
Rolling with additional batchLotes, mantendo a capacidade total
ImmutableInstâncias novas em ASG temporário; rollback rápido e seguro
Traffic splittingCanary: parte do tráfego para a versão nova
Blue/greenNovo ambiente e troca de URL (swap CNAME)
Pegadinha: "desenvolvedores querem só subir o código de uma aplicação web tradicional, sem gerenciar infraestrutura" = Elastic Beanstalk. Separe o banco do ambiente (RDS fora do Beanstalk) para não perder dados ao recriar o ambiente.

CI/CD com a família Code

CodeCommit / GitHub ─▶ CodeBuild (build + testes) ─▶ CodeDeploy (EC2, ECS, Lambda)
            └──────────────── orquestrado pelo CodePipeline ────────────────┘
  • CodeCommit: Git gerenciado (voltou a aceitar novos clientes em nov/2025).
  • CodeBuild: build e testes em containers, paga por minuto.
  • CodeDeploy: deploy in-place ou blue/green em EC2/on-premises; canary e linear em Lambda e ECS, com rollback automático por alarme.
  • CodePipeline: orquestra as etapas, inclusive aprovação manual.
  • CodeArtifact: repositório de pacotes (npm, pip, Maven).

AWS Systems Manager

Session ManagerShell na instância sem SSH, sem chave, sem bastion e sem porta aberta; sessões registradas no CloudTrail, S3 ou CloudWatch.
Run CommandExecutar comandos em centenas de instâncias de uma vez.
Patch ManagerAplicar patches de SO em janelas de manutenção, com relatório de conformidade.
Parameter StoreConfigurações e segredos simples, hierárquicos, com versão. SecureString criptografado com KMS.
AutomationRunbooks para tarefas operacionais (reiniciar, criar AMI, corrigir configurações).
Inventory / State ManagerSaber o que está instalado e manter a configuração desejada.

Requisito: SSM Agent na instância e uma role com a policy AmazonSSMManagedInstanceCore. Em sub-rede privada sem NAT, crie interface endpoints do SSM.
